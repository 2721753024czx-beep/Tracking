# GitHub 公开同步

本仓库公开可复用的核心源码、测试、工具和开源文档。每次完成可发布的功能或修复后，更新说明并提交、推送对应源码变化；GitHub 同步不替代本地数据备份。

## 公开范围

| 发布 | 留在本地 |
|---|---|
| 根 README、CHANGELOG、许可证与公开配置 | `.agent-memory/`、个人配置、凭据、环境文件 |
| `3.0/app/tracking3/`、`static/`、正式工具与测试 | 虚拟环境、模型权重、下载缓存、运行缓存与日志 |
| 明确选入的安装／同步工具与开源文档 | 自采或第三方原录像、裁图、截图、数据库、报告包、历史实验及备份 |

公开选择以仓库中的忽略规则、同步工具的实际检查和最终提交文件清单共同确定。新增目录不自动视为已批准公开；代码里的示例也使用通用路径和虚构配置。不要将开发者的专用实验启动入口当作公共安装入口。

## 每次更新的流程

1. 完成实现及与改动相符的测试；在根 README 和 CHANGELOG 中说明用户可见变化、运行条件与已知限制。
2. 从仓库根目录检查本次公开范围与内容：

   ```sh
   python3 '3.0/工具/sync_github.py' --check
   ```

   默认不带参数同样只做检查。工具入口为 [sync_github.py](../../工具/sync_github.py)，它会检查工作文件及暂存内容，拒绝不在公开范围内的文件、符号链接、敏感内容和不适合源码同步的大文件；单文件检查上限为 10 MiB，比 GitHub 的平台限制更严格。
3. 核对文件清单和差异后，提交并推送此次更新：

   ```sh
   python3 '3.0/工具/sync_github.py' --push --message '说明本次功能或修复及验证结果'
   ```

   工具仅安全暂存允许范围，存在变化时创建提交，再执行普通推送；没有文件变化但有未推送提交时仍会推送。它要求当前为 `main`，`origin` 指向不含内嵌凭据的 GitHub 地址。更多参数以 `--help` 为准。
4. 查看推送结果。失败时保留本地提交并记录原因，解决后继续同步；没有成功返回就不能记为已上传。扫描问题只定位文件和规则，不将敏感原文复制到公开文档或提交说明。

源文件、测试与相应公开文档应在同一次更新中保持一致。数据是否分发另按 [DATASETS.md](DATASETS.md) 判断；不得因为已获源码推送授权就将真实素材或数据库加入提交。

## 远程与冲突

本项目沿用 [2721753024czx-beep/Tracking](https://github.com/2721753024czx-beep/Tracking)，默认分支为 `main`。可用 `git remote -v` 核对当前克隆的远程。认证沿用使用者的 GitHub 工具或系统凭据管理，不把 token 写入代码、命令示例或日志。

`--check` 可以在未配置远程的本地仓库或 CI 的分离 HEAD 下做内容审计；只有 `--push` 必须位于 `main` 且配置有效的 GitHub `origin`。检查覆盖当前工作文件和暂存区，不追溯既有提交历史，也不替代人工内容与许可审核。

推送遇到远程更新时先检查差异并正常合并或变基，不使用强制推送覆盖他人历史。同步工具不应恢复实验备份、重建业务数据库或清空人工判断。遇到错误工作区、敏感文件或不明大文件时，先修正本次公开内容再推送。
